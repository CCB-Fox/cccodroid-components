# Yosys：Verilog 综合与形式化

本机装了 **Yosys 0.70**（命令行的版本依据就是 `yosys --version` 的输出）。
命令行批处理，没有图形界面。

## 一条铁律：一律用 `yosys-run`，别直接调 `yosys`

本机**直接调 `yosys`，只要走到 abc（工艺映射）就会永远卡住** —— 没有报错、没有超时、
一个字都不说，而 `synth` 默认就会走到 abc。
`yosys-run` 接的参数和 `yosys` 完全一样（`-p` / `-s` / `-c` / `-S` / 位置上的 `.ys`），
它在**你自己的命令流最前面**插一句 `scratchpad -set abc.exe …`，让 yosys 的 abc 改走
「写脚本文件、跑一次就收工」那条正常的路。插好之后，**所有会走到 abc 的写法都能直接跑**：

```sh
yosys-run -p "read_verilog ctr.v; synth; stat"                    # ✓ 不带 -noabc 也行（走了 ABC）
yosys-run -p "read_verilog ctr.v; synth_gatemate -luttree; stat"  # ✓
yosys-run -p "read_verilog ctr.v; synth_ecp5 -noabc9; stat"       # ✓
yosys-run -S ctr.v                                                # ✓ -S 也会被插上
yosys-run -c flow.tcl                                             # ✓ Tcl 里跑 synth 也行
yosys-run -s flow.ys                                              # ✓ .ys 里嵌套 script 调 abc 也行
```

只有一条要记住：**别绕过 `yosys-run` 去调 `$PREFIX/bin/yosys`** —— 那样没有注入，还是会卡死
（`yosys-run --selftest` 里有一条对照专门验证这件事）。

## 先自检

```sh
yosys-run --selftest        # 约 21 秒
yosys-run --why             # 把 ABC 那个坑和源码依据讲一遍
```

最后一行 `===== 总结 ===== 全部通过` 就是好的。它跑的是：综合一个 5 行模块看 `stat`、
写网表、显式走一遍 `abc`、形式等价检查、`synth_ice40`（ABC9 流程）、
以及**上面那五类以前会卡死的写法各跑一遍**，末尾还有一条「直接调 yosys 仍然会卡」的对照
（这条只提示、不算失败，免得别人的环境不一样时误报）。

## 基本用法

一小段 RTL 走完全程（下面每条都在本机跑过）：

```sh
cat > and2.v <<'EOF'
module and2(input a, b, output y);
  assign y = a & b;
endmodule
EOF

yosys-run -p "read_verilog and2.v; synth; stat"
```

一个 4 位计数器（`always @(posedge clk) q <= rst ? 4'd0 : q + 4'd1`）走 `synth; stat` 出来是：

```
        2   $_AND_
        1   $_NOT_
        4   $_SDFF_PP0_      ← 带同步复位的 D 触发器
        3   $_XOR_
```

注意是 `$_SDFF_PP0_`（**S** = 同步复位），不是 `$_DFF_PP0_` —— 找触发器别只 grep `$_DFF`。
（`synth -noabc` 跳过 ABC、只做内置映射，出来的单元名字不一样，也完全能用；
不想跑 ABC 时加它就是，但**不再是保命开关**。）

真要跑 ABC 的工艺映射（例如手里有 `.lib` 工艺库）就直接写，不用加任何东西：

```sh
yosys-run -p "read_verilog ctr.v; synth; abc -liberty cells.lib; stat"
```

## 常用命令（都实测过）

| 命令 | 作用 | 本机实测 |
|---|---|---|
| `read_verilog x.v` | 读 Verilog | ✓ |
| `read_verilog -sv x.sv` | 读 SystemVerilog（`logic` / `always_ff` 认） | ✓ |
| `hierarchy -top m` | 指定顶层、拉平层次 | ✓ |
| `proc` / `opt` / `memory` / `techmap` / `flatten` | 单趟 pass，逐步调的时候用 | ✓ 各自都能单独跑 |
| `synth` | 默认综合流程（会走 ABC） | ✓ |
| `synth -noabc` | 同一套流程但跳过 ABC | ✓ |
| `abc` | 工艺映射，写 `abc` 就行（`abc.exe` 由 yosys-run 注入） | ✓ |
| `stat` | 看规模（线数 / 单元数 / 单元清单） | ✓ |
| `write_verilog x.v` | 写门级网表（开头是 `/* Generated by Yosys … */`） | ✓ 再读回来是 `$and` 这样的字级单元 |
| `write_json x.json` | 写 JSON（`jq` 能直接读，顶层是 `modules`） | ✓ |
| `write_blif x.blif` | 写 BLIF | ✓ |
| `show -format svg -prefix 名字 -viewer none` | 出电路图 SVG | ✓（graphviz 在底座里） |
| `equiv_*` | 形式等价检查 | ✓ 见下 |
| `sat` | SAT 求解（本机用 minisat） | ✓ 见下 |

### FPGA 流程（`synth_ice40` / `synth_ecp5` / `synth_xilinx` / `synth_gowin` …）

这些走的都是 **ABC9**，本来就不卡（17 条流程逐个实测 rc=0）；`yosys-run` 的注入也不影响它们
（abc9 不读 `abc.exe`）。直接跑：

```sh
yosys-run -p "read_verilog ctr.v; synth_ice40; stat"
```

**`synth_easic` 除外**：它要 eTools 的库文件（`…/opt/eTools/data_ruby28/…lib`，本机没有），
会以一句 `ERROR: File … not found` 失败 —— 是明确报错，不是卡死（以前会卡，现在不会了）。

### 写法上的坑

- **位置参数上的脚本必须以 `.ys` 结尾**。yosys 靠后缀区分「脚本」和「输入文件」：
  给它一个没有后缀的文件，它会以为是输入文件，然后报
  `Can't guess frontend for input file … (missing -f option)!`。
  （`-s <文件>` 不受这条限制。）
- `-p "a; b; c"` 里命令用**分号 + 空格**隔开，这是 yosys 自己的规矩。
- 脚本文件里 `#` 是注释。
- **自己别写 `abc -exe yosys-abc`，也别把 scratchpad 的 `abc.exe` 设回默认那个路径** ——
  那会让 yosys 退回卡死那条路（见下面「ABC 那个坑」）。

## 形式验证：两段代码等价吗

实测跑通的完整流程（gold 和 gate 是同一个函数的两种写法）：

```sh
cat > gold.v <<'EOF'
module top(input a, input b, input c, output y);
  assign y = (a & b) | (~a & c);
endmodule
EOF
cat > gate.v <<'EOF'
module top(input a, input b, input c, output y);
  wire t1, t2, nb;
  assign nb = ~a;
  assign t1 = a & b;
  assign t2 = nb & c;
  assign y = t1 | t2;
endmodule
EOF

yosys-run -Q -T \
  -p "read_verilog gold.v; prep -top top; rename top gold; design -stash gold" \
  -p "read_verilog gate.v; prep -top top; rename top gate; design -copy-from gold -as gold gold" \
  -p "equiv_make gold gate equiv; hierarchy -top equiv; equiv_simple; equiv_status -assert"
```

判出等价时会打印 `Equivalence successfully proven!`。**顺序不能换**：
先把 gold 用 `design -stash` 存起来，再把 gate 读进来、再把 gold 取回来，最后才 `equiv_make`。

## SAT：证明 / 举反例

```sh
# 成立：打印 "SAT proof finished - no model found: SUCCESS!"（后面跟一张 ASCII 大图）
yosys-run -Q -T -p "read_verilog and2.v; prep -top and2; sat -set a 1 -prove y b"

# 不成立：打印一张信号表当反例（a=0 b=0 y=0）
yosys-run -Q -T -p "read_verilog and2.v; prep -top and2; sat -prove y 1"
```

`-set 信号 值` 加前提，`-prove 信号 值`（值也可以是信号）说「要证这个」。
退出码在两种情况下都是 0 —— **别拿退出码当结论，要看输出里是 `SUCCESS!` 还是那张反例表**。

## 出图给用户看

graphviz 在底座里，直接能用：

```sh
yosys-run -Q -T -p "read_verilog and2.v; prep -top and2; show -format svg -prefix sch -viewer none"
```

会得到 `sch.svg`。**一定要写 `-viewer none`** —— 不写的话 yosys 会去找 `xdot` 打开图，
本机没有这个程序；**也要写 `-prefix`**，不写它会往 `~/.yosys_show.svg` 写。
把 svg 拷到 `/sdcard/cccodroid/` 给用户，应用内查看器能直接看。

## ABC 那个坑（要跟用户解释时用）

```
yosys-run --why
```

对着 Yosys 0.70 的源码看，机制是这样的：

- yosys 挑 abc 可执行文件时先读设计里的 scratchpad 变量 **`abc.exe`**，默认值是
  **`<yosys 自己所在目录>/yosys-abc`**（`passes/techmap/abc.cc:2040` +
  `kernel/yosys.cc:661`，不是字面量 `"yosys-abc"`）；
- 然后按**字符串相等**选路（`passes/techmap/abc.cc:147`）：
  相等 → 走**常驻 ABC 协进程**（管道协议、复用同一个 abc 进程）—— **本机这条会互等卡死**；
  不等 → 把 abc 脚本写成临时文件、跑一次 `"<exe>" -s -f <script>` —— 正常。
- 卡死那条路上，yosys 喂完脚本不关管道写端、也不发 `quit`，ABC 停在 `abc 07> ` 等下一条命令，
  两边互等（翻 `/proc/<yosys 的 pid>/fd` 能看到它一直攥着那个写端 pipe）。
  `env -u LD_PRELOAD`、`enosys-run` 都试过，一样卡 —— 不是 seccomp 的事。

`yosys-run` 的做法：在**用户自己的命令流最前面**插一句
`scratchpad -set abc.exe $PREFIX/share/cccodroid/components/yosys/abc-exe`
（`abc-exe` 就是“另一个字符串”，内容只是把参数转给真的 `yosys-abc`）。
插的位置由 yosys 自己的执行顺序决定（`kernel/driver.cc:604-668`）：
`-s`/`-c` 脚本在 `-p` **之前**跑、`-S` 的 synth 也在 `-p` **之前**，所以分别是
「写进脚本第一行」「把 `-S` 改成等价的 `-p`」；`-p` 和位置上的 `.ys` 就插在命令串/文件开头。

## 限制

- **没有图形界面**（没有 `xdot` / `display`）。看电路就导 SVG。
- **ABC 真正做工艺映射需要 `.lib` 工艺库**，库里没有；不配库时 `abc` 只做逻辑优化。
- 综合大设计吃内存，本机是手机，几千行 RTL 要留神；`stat` 出来的规模先看一眼再上大的。
- 只做**命令行**：读 RTL、综合、写网表、形式化。**仿真不是它的事** —— 这个组件里没有仿真器。
