# Yosys：Verilog 综合与形式化

本机装了 **Yosys 0.70**（命令行的版本依据就是 `yosys --version` 的输出）。
命令行批处理，没有图形界面。

## 两条铁律

**1. 一律用 `yosys-run`，不要直接调 `yosys`。**

本机的 `yosys` 只要走到 ABC（工艺映射）那一步，就会**永远卡住** —— 没有报错、没有超时、
一个字都不说。原因和证据见下面「ABC 那个坑」。`yosys-run` 接的参数和 `yosys` 完全一样
（`-p` / `-s` / 位置上的 `.ys` 文件都认），它负责绕开这个坑，并且在真要卡住时当场拦住你。

**2. `synth` 一定要带 `-noabc`。**

（只针对通用的 `synth` 这一条；`synth_ice40` 这类具体流程不用 —— 它们走 ABC9，见下面
「FPGA 流程」。`synth` 的 `-noabc` 是保命的，`synth_ice40` 的 `-noabc` 是另一件事，
别混。）

不带就是卡死。`synth -noabc` 出来的门级网表、`stat` 统计、`write_verilog` 都完全正常：

```sh
yosys-run -p "read_verilog and2.v; synth -noabc; stat"
```

真要跑 ABC（例如手里有 `.lib` 工艺库）时，先 `-noabc` 综合，再单独调 `abc`；
`yosys-run` 会自动给 `abc` 补上本机需要的 `-exe`（实测能跑通，而且 ABC 真会优化：
4 位计数器综合出来的 `$_AND_`/`$_XOR_` 变成了 `$_NAND_`/`$_XNOR_`）：

```sh
yosys-run -p "read_verilog ctr.v; synth -noabc; abc -liberty cells.lib; stat"
```

**FPGA 流程同样要经过 `yosys-run`**（`synth_ice40` / `synth_ecp5` / `synth_xilinx` /
`synth_gowin` / `synth_anlogic` … 一个都别直接调 `yosys`）。好消息是这些流程走的是
**ABC9**，而 ABC9 在这台机器上**不卡**（17 条流程逐个实测 rc=0）—— 所以它们直接跑就行：

```sh
yosys-run -p "read_verilog ctr.v; synth_ice40; stat"        # ✓ 能跑通（abc9）
```

例外只有两条，`yosys-run` 会替你挡住（它们走的是**裸 abc**，必卡）：

| 命令 | 怎么办 |
|---|---|
| `synth_easic` | 本机不支持（映射用 `abc -liberty`，还要 eTools 的库文件） |
| `synth_gatemate -luttree` | 加 `-abc_new`（等价开关，实测 rc=0），或者不用 `-luttree` |

另外 **`-c <tcl 脚本>` 不支持**（tcl 里能随便调命令，扫不到）：把要跑的写成 `.ys`，
用 `-s` 或位置参数交给 `yosys-run`。

## 先自检

```sh
yosys-run --selftest
```

最后一行 `===== 总结 ===== 全部通过` 就是好的（约 3 秒）。
它跑的是：综合一个 5 行模块看 `stat`、写网表、走一遍 ABC、形式等价检查、
`synth_ice40`（ABC9 流程）能跑完、`abc9` 能跑完、以及三类守卫（`synth` / `-luttree` / `-c`）
真的拦得住。

`yosys-run --why` 把 ABC 那个坑和整个 `synth` 家族的实测结论讲一遍。

## 基本用法

一小段 RTL 走完全程（下面每条都在本机跑过）：

```sh
cat > and2.v <<'EOF'
module and2(input a, b, output y);
  assign y = a & b;
endmodule
EOF

yosys-run -p "read_verilog and2.v; synth -noabc; stat"
```

`stat` 会打出单元清单（`$_XXX_` 是内部单元名，`$_AND_` / `$_DFF_PP0_` / `$_NOT_` / `$_XOR_`
这些就是综合出来的门）：

```
        1   $_AND_
```

一个 4 位计数器（`always @(posedge clk) q <= rst ? 4'd0 : q + 4'd1`）综合出来是：

```
        2   $_AND_
        1   $_NOT_
        4   $_SDFF_PP0_      ← 带同步复位的 D 触发器
        3   $_XOR_
```

注意是 `$_SDFF_PP0_`（**S** = 同步复位），不是 `$_DFF_PP0_` —— 找触发器别只 grep `$_DFF`。

## 常用命令（都实测过）

| 命令 | 作用 | 本机实测 |
|---|---|---|
| `read_verilog x.v` | 读 Verilog | ✓ |
| `read_verilog -sv x.sv` | 读 SystemVerilog（`logic` / `always_ff` 认） | ✓ |
| `hierarchy -top m` | 指定顶层、拉平层次 | ✓ |
| `proc` / `opt` / `memory` / `techmap` / `flatten` | 单趟 pass，逐步调的时候用 | ✓ 各自都能单独跑 |
| `synth -noabc` | 默认综合流程（**必须带 -noabc**） | ✓ |
| `abc` | 工艺映射；写 `abc` 就行，`-exe` 由 yosys-run 补 | ✓ |
| `stat` | 看规模（线数 / 单元数 / 单元清单） | ✓ |
| `write_verilog x.v` | 写门级网表（开头是 `/* Generated by Yosys … */`） | ✓ 再读回来是 `$and` 这样的字级单元 |
| `write_json x.json` | 写 JSON（`jq` 能直接读，顶层是 `modules`） | ✓ |
| `write_blif x.blif` | 写 BLIF | ✓ |
| `show -format svg -prefix 名字 -viewer none` | 出电路图 SVG | ✓（graphviz 在底座里） |
| `equiv_*` | 形式等价检查 | ✓ 见下 |
| `sat` | SAT 求解（本机用 minisat） | ✓ 见下 |

### 写法上的坑

- **位置参数上的脚本必须以 `.ys` 结尾**。yosys 靠后缀区分「脚本」和「输入文件」：
  给它一个没有后缀的文件，它会以为是输入文件，然后报
  `Can't guess frontend for input file … (missing -f option)!`。
  （`-s <文件>` 不受这条限制。）
- `-p "a; b; c"` 里命令用**分号 + 空格**隔开，这是 yosys 自己的规矩。
- 脚本文件里 `#` 是注释。

## 形式验证：两段代码等价吗

实测跑通的完整流程（gold 和 gate 是同一个函数的两种写法）：

```sh
cat > gold.v <<'EOF'
module top(input a, input b, input c, output y);
  assign y = (a & b) | (~a & c);
endmodule
EOF
cat > gate.v <<'EOF'
module top(input a, input b, input c, output y);
  wire t1, t2, nb;
  assign nb = ~a;
  assign t1 = a & b;
  assign t2 = nb & c;
  assign y = t1 | t2;
endmodule
EOF

yosys-run -Q -T \
  -p "read_verilog gold.v; prep -top top; rename top gold; design -stash gold" \
  -p "read_verilog gate.v; prep -top top; rename top gate; design -copy-from gold -as gold gold" \
  -p "equiv_make gold gate equiv; hierarchy -top equiv; equiv_simple; equiv_status -assert"
```

判出等价时会打印 `Equivalence successfully proven!`。**顺序不能换**：
先把 gold 用 `design -stash` 存起来，再把 gate 读进来、再把 gold 取回来，最后才 `equiv_make`。

## SAT：证明 / 举反例

```sh
# 成立：打印 "SAT proof finished - no model found: SUCCESS!"（后面跟一张 ASCII 大图）
yosys-run -Q -T -p "read_verilog and2.v; prep -top and2; sat -set a 1 -prove y b"

# 不成立：打印一张信号表当反例（a=0 b=0 y=0）
yosys-run -Q -T -p "read_verilog and2.v; prep -top and2; sat -prove y 1"
```

`-set 信号 值` 加前提，`-prove 信号 值`（值也可以是信号）说「要证这个」。
退出码在两种情况下都是 0 —— **别拿退出码当结论，要看输出里是 `SUCCESS!` 还是那张反例表**。

## 出图给用户看

graphviz 在底座里，直接能用：

```sh
yosys-run -Q -T -p "read_verilog and2.v; prep -top and2; show -format svg -prefix sch -viewer none"
```

会得到 `sch.svg`。**一定要写 `-viewer none`** —— 不写的话 yosys 会去找 `xdot` 打开图，
本机没有这个程序；**也要写 `-prefix`**，不写它会往 `~/.yosys_show.svg` 写。
把 svg 拷到 `/sdcard/cccodroid/` 给用户，应用内查看器能直接看。

## ABC 那个坑（要跟用户解释时用）

```
yosys-run --why
```

要点：yosys 把 ABC 脚本从管道喂给 `yosys-abc`，喂完**不关管道的写端**、也不发 `quit`；
ABC 读完脚本就停在交互提示符 `abc 07> ` 上等下一条命令，两边互等。
翻 `/proc/<yosys 的 pid>/fd` 能看到它一直攥着那个写端 pipe。
（`env -u LD_PRELOAD`、`enosys-run` 都试过，一样卡 —— 不是 seccomp 拦系统调用的事。）

`synth` 里 abc 夹在 `fine` 段**内部**（`yosys -p "help synth"` 能打出整条流程），
没有独立标签，所以 `-run begin:fine` 这类切法也绕不过去。
`yosys-run` 的办法是给 `abc` 补 `-exe <fifo 包装>`：包装逐行转发脚本，
看到 yosys 的哨兵 `YOSYS_ABC_DONE` 就补一个 `quit`，ABC 于是正常退出。

## 限制

- **没有图形界面**（没有 `xdot` / `display`）。看电路就导 SVG。
- **ABC 真正做工艺映射需要 `.lib` 工艺库**，库里没有；不配库时 `abc` 只做逻辑优化。
- 综合大设计吃内存，本机是手机，几千行 RTL 要留神；`stat` 出来的规模先看一眼再上大的。
- 只做**命令行**：读 RTL、综合、写网表、形式化。**仿真不是它的事** —— 这个组件里没有仿真器。
