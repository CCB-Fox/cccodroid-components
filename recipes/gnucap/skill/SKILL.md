# gnucap：电路仿真

本机装了 gnucap 2021.01.07（`master 2021.01.07`）。写电路文件，命令行批处理跑分析。

**和 ngspice 是两套语法**，别把 ngspice 的网表直接拿来用。三条最大的区别：

| | ngspice | gnucap |
|---|---|---|
| 命令前缀 | `.tran`，或者放进 `.control` 块 | **必须带点**：`.tran`；写成 `tran` 会被当成传输线元件 |
| 探针 | `.control` 里 `print v(out)` | `.print tran v(out)`，而且**必须写在分析命令前面** |
| 控制块 | `.control … .endc` | **没有**，命令直接写 |

## 先自检

```sh
gnucap-run --selftest
```

最后一行 `===== 总结 ===== 瞬态=OK 末值=…V` 就是好的。约 0.1 秒。
它真跑一个 RC 充电电路，把 5τ 处的电压和解析解 5·(1−e⁻⁵)=4.96631 V 对一遍。

## 跑一个电路

```sh
gnucap-run <电路文件> [gnucap 的其它参数…]
```

**`gnucap-run` 不是装饰**：gnucap **出错了也返回 0**（元件名写错、命令不存在、探针没生效，
退出码全是 0）。所以包装脚本会扫它输出里的错误标记（`^ ? …`），见到就返回 1 并把原文打出来。
直接调 `gnucap -b` 很容易把「没算成」当成「算完了」。

## 一个完整的例子

```
* RC 充电                          ← 第一行：标题（习惯写法，gnucap 也照收）
V1 in 0 PULSE(0 5 0 1n 1n 1 2)     ← 元件：名字 节点 节点 … 值
R1 in out 1k
C1 out 0 1u
.print tran v(out)                 ← 探针：先声明要看的量
.tran 0 5m 0.05m                   ← 再写分析：起点 终点 步长
.end
```

```
$ gnucap-run rc.ckt
* RC
#Time       v(out)
 0.         0.
 50.u       0.24389
 …
 0.005      4.9663
```

**输出是工程计数法**：`50.u` = 50 µs、`10.K` = 10 kΩ、`4.9663` 就是 4.9663。读结果时按这个换算。

**单位后缀**（实测，用分压器反推过）：`1k` / `1K` / `1000` 都是 1 kΩ；`1meg`（也可写 `1megohm`）
才是 1 MΩ；`1m` 和 **`1M` 都是「毫」**—— 写 `1M` 想表示兆的话会得到 1 mΩ，差九个数量级。
大写小写不区分，只有 `meg` 是兆。

## 四种分析（这版有 `.tran` `.op` `.dc` `.ac` `.fourier`）

```
* 瞬态
.print tran v(out) v(in)
.tran 0 5m 0.05m              ← 起点 终点 步长

* 工作点：第一列是温度（27 °C），不是被测量的值
.print op v(out) v(in)
.op

* 直流扫描
.print dc v(out)
.dc V1 0 5 1                  ← 源 起点 终点 步长

* 交流：源要写 AC 幅值
V1 in 0 AC 1
.print ac v(out)              ← 给的是幅值；要 dB 就自己算 20·log10
.ac 10 10k                    ← 起点 终点（Hz）
```

没有 `.noise` / `.tf` / `.disto` / `.sens`（实测都报 `no match`），要噪声或传递函数用 ngspice。

**源的类型**（实测都认）：`DC 5`、`AC 1`、`PULSE(0 5 0 1n 1n 1 2)`、
`SIN(0 5 1k)`；括号可有可无（`PULSE 0 5 0 1n 1n 1 2` 也行）。

## 结果写文件、画波形

```sh
gnucap-run rc.ckt > out.dat              # 用 shell 重定向就行
```

也可以写在分析命令上：`.tran 0 5m 0.05m > out.dat`（实测可用，数据进文件，stdout 上就没有了）。

画波形**优先手写 SVG，不用装任何东西**：把 `out.dat` 两列读进来生成 `<polyline>`，
产出 `.svg` 放到 `/sdcard/cccodroid/` 给用户在应用内查看器看；
要 PNG 就 `magick -density 96 图.svg 图.png`（本机实测可用）。
`matplotlib` 本机没装，要装先问用户。

## 常见坑

- **`.print` 写在分析命令后面 → 探针不生效，结果里只有时间列，而且一声不吭、退出码还是 0。**
  实测就踩到过。`gnucap-run` 会专门检查这种情况并返回 1。
  gnucap 是按顺序执行的：先 `.print` 声明，再 `.tran`/`.op`/`.dc`/`.ac` 执行。
- **命令少了点前缀就不是命令**：`tran 0 5m` 会被当成一个叫 `tran` 的 **T 元件（传输线）**，
  报 `need 1 more nodes`，然后这一行就被丢掉了。
- **`.op` 输出的第一列是温度**（27.），表头只有一个 `#`，别把它当电压读。
- **步长影响精度**：gnucap 的内部步长跟着打印间隔走。1 kΩ×1 µF（τ=1 ms）用 `.tran 0 5m 1m`
  算出来 5τ 处是 4.9712 V，比解析解 4.96631 V 高约 0.1%；把步长收到 `0.05m` 就是 4.9663 V，
  基本一位不差。**要准就把步长给细**，`.print` 出来的行多点没关系。
- 少了 `.end` **不算错**：实测 gnucap 一直读到文件尾，结果是对的。
- 每次启动那 9 行版权 banner 已经由 `gnucap-run` 去掉了。
